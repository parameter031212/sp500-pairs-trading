# A–D 페어 선정 및 청산·손절 144개 실험

`notebooks/Run_144_Experiments.ipynb`에서 실제 데이터 폴더와 날짜를 지정하고 위에서부터 실행합니다. `Start_Here.ipynb` 마지막에도 실행 셀을 추가했습니다. 공통 설정은 `configs/selection_study.toml`입니다.

## 실험 순서와 이름

4모델 × 추정 12/24개월 × 청산 0/+0.5 × 손절 3/3.5/4/4.5/5/5.5/6/6.5/7 = **144개**입니다. A의 36개가 끝나면 B → C → D 순서로 실행합니다. 각 모델 안에서는 추정 12 → 24개월, 청산 0 → +0.5, 손절 작은 값 → 큰 값 순서입니다.

예: `C_F24_Exit0p5_Stop4p5`는 C, 추정 24개월, 평균 도달 전 ±0.5σ에서 청산, 손절 4.5σ입니다. `Exit0p5`는 조기 청산, `Exit0p0`은 평균 청산입니다.

| 모델 | 공통 기준에 추가하는 보조 필터 |
|---|---|
| A | 없음 |
| B | 추정 구간의 일별 로그 수익률 상관계수 > 0.5 |
| C | 직전 12개월 사전 모의거래의 비용 차감 샤프 > 0, 실제 진입 ≥ 3건 |
| D | B와 C 모두 |

모두 입력 자료의 동일 `sector` 안에서 Engle–Granger 검정을 합니다. 공통 커버리지, 양의 β 0.3–3, 반감기 5–30일, 명목 공적분 p < 0.05, 최대 20페어를 기본으로 유지합니다. 2026-09-19부터 섹터당·종목당 페어 수 제한은 기본 해제하며, `selection.max_per_sector=0`, `selection.max_per_stock=0`으로 표시합니다. 양의 정수를 지정하면 해당 제한만 다시 적용합니다. 최종 통과 페어는 EG t통계량이 낮은 순서로 선정합니다. 상관관계나 샤프로 순위를 다시 매기지 않습니다. 유효 페어가 적으면 남은 슬롯은 현금입니다. 회귀 방향은 기본 `fixed`이며 기존 양방향 옵션도 사용할 수 있습니다.

## 두 가지 청산 조건

`exit_z`는 양의 Z에서 진입했을 때의 목표입니다. 음의 Z에서 진입하면 목표 부호를 반대로 적용합니다.

| 설정 | 양의 Z에서 진입한 숏 스프레드 | 음의 Z에서 진입한 롱 스프레드 | 의미 |
|---|---|---|---|
| 0 | Z ≤ 0 | Z ≥ 0 | 평균 도달/통과 |
| +0.5 | Z ≤ +0.5 | Z ≥ −0.5 | 평균 도달 전 조기 청산 |

정확히 목표 Z를 찍을 필요는 없습니다. 목표를 넘으면 신호를 내고 **다음 거래일 종가**에 체결합니다. 트레일링은 사용하지 않습니다. 추정 구간 종료일 신호도 첫 거래일에 체결할 수 있습니다.

진입은 기존 기준인 **2 ≤ |Z| < 손절선**입니다. 이미 손절선을 넘은 신호에는 새로 진입하지 않습니다. 따라서 이번 실험에서 손절선을 바꾸면 진입 가능한 상한도 함께 변합니다. 순수한 손절 효과만 분리한 실험은 아닙니다. 체결일까지 Z가 손절선을 넘으면 예정된 진입을 체결한 뒤 다음 종가 청산 신호를 낼 수 있습니다.

방향에 따른 불리한 이탈에 손절을 적용합니다. 최대 보유기간은 체결일 포함 60거래일이고 구간 마지막 날은 강제 청산합니다. 손절·시간청산 뒤에는 그 거래 구간에서 재진입하지 않습니다. 평균 청산 뒤에는 다시 진입할 수 있습니다. 이 규칙은 모든 실험에서 같습니다.

## 선정용 샤프를 계산하는 방법

현재 거래 시작 전 12개월을 기본 **6개월짜리 두 블록**으로 나눕니다. 각 블록 시작 전에 과거 F개월(12 또는 24)로 α·β·스프레드 평균·표준편차를 다시 추정하고, 블록 거래 동안 고정합니다. 현재 시점에서 추정한 계수를 과거 12개월 전체에 소급 적용하지 않습니다. 양방향 옵션이면 각 과거 블록 당시 자료로 방향도 선택합니다.

선정용 모의거래는 모든 실험에서 **진입 2, 청산 0, 손절 3.5σ**로 고정합니다. 최대 보유기간·재진입·비용·현금 이율은 공통 설정을 따릅니다. 각 블록 마지막에 청산하며, 첫 블록 종료 NAV로 다음 블록을 시작합니다. 두 블록의 모든 시장 일별 순수익률을 합쳐 연율화 샤프를 계산합니다. 수수료·슬리피지·설정된 대차비용을 차감하며, 무포지션 날짜도 포함합니다. 진입은 신호 수가 아닌 실제 체결 수입니다. `pretrade_blocks`에 각 블록의 추정·거래 날짜와 계수를 기록합니다.

비교의 혼선을 줄이기 위해 청산/손절 실험값은 선정용 샤프에 반영하지 않습니다. 같은 모델·F·거래 구간에서는 18개 조합 모두 동일한 페어를 사용합니다. 과거 β가 허용 범위를 벗어나거나 필요한 가격이 없으면 해당 후보의 샤프를 계산할 수 없는 것으로 표시하고 제외합니다. 블록마다 별도의 공적분/상관/반감기 통과를 요구하지는 않습니다. 해당 검정과 필터는 현재 선정 시점의 추정 구간에서 적용합니다.

2020년 시작·F24·사전 모의거래 12개월이면 첫 사전 추정은 **2017년부터** 필요합니다. 시작 날짜와 추정개월은 거래 구간별로 계산합니다.

가격 시작일이 2005-09-27인 현재 자료에서 A–D 전체를 1월/7월 반기 구간으로 비교할 때, 과거 자료 길이를 충족하는 첫 시작일은 **2009-01-01**입니다. 예를 들어 2008년 시작·F24·사전거래 12개월은 2005-01-01부터 가격을 요구하므로 부족합니다. A/B만 실행하면 사전거래가 없어 필요한 최대 과거 기간은 24개월이지만, C/D와 비교하려면 공통 기간으로 맞춥니다. 각 종목의 관측치·결측률 검사는 별도로 진행합니다.

노트북의 입력 확인 셀은 **실행 중인 cfg의 날짜**, 모델별 필요한 가격 시작일, 실제 자료 시작일, 기간 충족 여부, 동일 거래 주기에서 가능한 시작 구간을 표시합니다. `PARAMETERS`의 날짜만 바꾸고 `cfg` 생성 셀을 다시 실행하지 않으면 이전 설정이 남습니다. 시작일을 수정했다면 설정 셀부터 다시 실행하세요. 프로그램이 날짜를 자동 변경하거나 부족한 가격을 보간하지는 않습니다. 실행 전 검사에서 모든 모델의 요구 기간을 함께 확인하고, 가장 긴 기간을 기준으로 오류를 안내합니다.

## 합병 발표 이후의 공통 규칙

`corporate_actions.enabled=true`이며 A–D, 12/24개월, 모든 청산·손절 조합 및 선정용 사전 모의거래에 똑같이 적용합니다.

1. 선정 시점에 발표가 알려진 피인수 종목은 후보에서 제외합니다. 아직 발표되지 않은 사건으로 과거의 선정을 바꾸지 않습니다.
2. 거래 중 발표가 알려지면 신규 진입과 대기 중인 진입 주문을 취소합니다.
3. 이미 보유 중이면 다음 거래 가능한 종가에 **양쪽 종목을 모두 청산**합니다. 청산일까지 발생한 손익·수수료·슬리피지·설정된 대차비용을 계산합니다.
4. 해당 페어는 그 거래 구간의 나머지 기간에 재진입하지 않고 현금으로 둡니다. 구간 중 다른 페어로 교체하지 않습니다. 합병 취소가 공식 확인되어 차단 해제일이 기록되면, 이후 재선정 시점부터 다시 후보가 될 수 있습니다.

장 마감 전 발표임이 확인되면 당일을 인지일로, 발표 시각이 없거나 장 마감 후이면 다음 시장 거래일을 인지일로 씁니다. 현재 배포 일정은 날짜만 확인했으므로 모두 후자입니다. 예를 들어 월요일 날짜만 확인된 발표는 화요일 신규 진입 차단·청산 신호, 수요일 종가 청산입니다. 정규 청산 주문이 이미 실행되었다면 그 체결 사유를 유지합니다.

공식 거래 종료일은 해당 날짜 이후 CSV에 숫자가 남아 있어도 체결하지 않도록 확인하는 용도입니다. 종료일을 미리 안 것처럼 그 전날 청산하지 않습니다. 보유 중 가격이 없거나 거래정지 상태라서 평가·청산할 수 없으면 기업행동 정산 자료가 필요하므로 오류를 유지합니다.

`reference_data/merger_events.csv`에 발표일·확인 시점·종목·공식 출처를 저장합니다. **35개 사건을 수집한 일정표이며 전 종목·전 기간을 망라한 자료는 아닙니다.** 완료된 합병만 반영하는 편향을 줄이기 위해 WLTW–AON 취소 사건도 포함했지만, 완전한 표본이라는 뜻은 아닙니다. 적용 대상과 데이터 한계는 [합병 일정 설명](../reference_data/README.md)을 확인하세요.

종목 제외는 `universe_audit.csv`의 `merger_announced`, 실제 합병 청산은 `trades.csv`의 `exit_reason=merger_announcement` 및 `merger_event_ids`, 청산 건수는 비교표의 `merger_announcement_exits`에서 확인합니다. 일정 해시도 저장하므로 다른 일정으로 기존 실험을 이어 붙일 수 없습니다.

기존 `selection_study_216`의 성과는 이전 거래 정책의 결과이며, `selection_study_144_mergers`는 집중 제한을 적용했던 결과입니다. **제한을 해제한 실험은 새 `selection_study_144_no_concentration_caps`에서 A부터 다시 계산**합니다. 원본 데이터와 기존 결과는 보존합니다.

## 저장, 중단, 이어서 실행

기본 결과 폴더는 `results/selection_study_144_no_concentration_caps/`입니다.

- `comparison.csv`: 144개 전체 계획, 상태, 파라미터, 완료된 실험의 성과와 오류.
- `model_A_comparison.csv` 등: 모델별 36개 비교표.
- `study_manifest.json`: 진행 상태, 설정·입력 자료·코드·패키지 식별 정보.
- `model_A/실험이름/attempt_001/`: 설정, 일별 계좌 NAV, 거래 기록, 선정 페어, 구간별 결과, 사용한 `merger_events.json` 일정 사본.
- `selection_audits/A_F12/` 등: 재사용되는 후보 검정·종목·회귀 방향 감사표.
- `selection_cache/`: 재시작 후에도 재사용하는 통계량과 선정 결과. 임의로 편집하지 않습니다.

기본 `compact` 출력은 페어별 일별 원장·종목별 노출·실험별 그림을 생략해 저장 공간을 줄입니다. 필요하면 처음 실행할 때 `output_profile="full"`을 지정하세요.

노트북 실행 중 중단하거나 종료한 뒤 같은 설정으로 다시 실행하면 완료 파일이 있는 실험은 건너뜁니다. 중단된 실험은 새 `attempt` 폴더에서 다시 실행합니다. `MODELS=["A"]`로 먼저 A만 돌린 뒤, 동일 결과 폴더에서 `MODELS=["B","C","D"]` 또는 전체 모델로 이어갈 수도 있습니다. `MODELS` 순서를 바꾸더라도 실행 순서는 A → B → C → D입니다.

가격 결측 등으로 실패한 실험은 실패 상태로 남기고 다른 조합을 계속 진행합니다. 실패한 실험에 성과를 부여하지 않습니다. 실패 재시도는 `retry_failed=True`로 명시합니다. **144개가 모두 성공해야 전체 상태가 complete**입니다. 설정·가격·합병 일정·코드·패키지가 달라지면 기존 결과와 섞지 않고 새 결과 폴더를 요구합니다. 창을 여러 개 열어 같은 폴더에서 동시에 실행하는 것도 차단합니다.

확인된 합병 발표에는 아래 공통 정책을 적용합니다. 일정표에 없는 사건이나 일반 가격 결측은 여전히 실패로 기록합니다. 가격을 보간하거나 마지막 가격으로 가상 청산하지 않습니다. 사전 모의거래에서 해결되지 않은 가격 문제가 생기면 해당 후보를 탈락시킵니다.

```bash
python run_backtest.py study --config configs/selection_study.toml --data-dir "/path/to/data"
# A만 먼저 실행: 같은 결과 폴더에 저장하고 다음 명령에서 이어하기
python run_backtest.py study --config configs/selection_study.toml --data-dir "/path/to/data" --models A
```

기본 2020–2025년 전체 기간의 비교는 `exploratory_not_holdout`입니다. 최종 test 기간에서는 탐색을 허용하지 않습니다. 가장 높은 샤프를 고른 것만으로 일반화 성능을 입증하지는 않습니다. 이 코드는 페어 선정·청산·손절 비교를 구현하며, 공적분 붕괴 탐지 모형은 아직 추가하지 않았습니다.
